Application Modernization — Microsoft Guidance

Application modernization is a continuous cycle of assessment, planning, and execution. Microsoft provides a proven framework to help organizations modernize with confidence.

The 6 Rs of Application Modernization

Rehost

Lift & shift to cloud without code changes

Replatform

Move to new runtime with minimal changes

⭐ Refactor

Upgrade code and architecture for modern frameworks

Rebuild

Start over when costs outweigh benefits

Retire

Decommission apps no longer needed

Retain

Keep as-is when not ready

Modernization Lifecycle

PhaseActivitiesKey Outcomes
AssessEvaluate IT assets, identify legacy systems, technical debtApplication inventory, risk profile
PlanChoose modernization strategy (6 Rs), prioritize by ROIMigration roadmap, effort estimates
LaunchExecute proof of concept, validate strategyValidated approach, stakeholder buy-in
FoundationEnd-to-end modernization, cloud-first PaaS adoptionModern runtime, CI/CD pipelines
ExpandManaged services, API-first, performance tuningCloud-native capabilities
OptimizeContinuous improvement, cost optimization, DevSecOpsLower TCO, higher reliability

Our Approach: Refactor — We're upgrading our .NET 6 application to .NET 10 LTS. This is the "Refactor" strategy: modernizing the framework and dependencies to enable future UI innovation while maintaining behavioral equivalence.

🟢 Target State: .NET 10 LTS

Same application, modern runtime. C# 14, improved performance, post-quantum crypto, NativeAOT. Foundation for UI modernization next spring.

Why Upgrade Before UI Changes?

🛡️ Security

.NET 6 is end of life. No more security patches means growing vulnerability exposure. .NET 10 LTS provides 3 years of support.

⚡ Performance

.NET 10 delivers JIT improvements, better async, and NativeAOT enhancements. A faster runtime means a faster UI — before writing any frontend code.

🧱 Foundation

Modern UI frameworks (Blazor United, .NET Aspire) require .NET 8+. Upgrading now unlocks the entire ecosystem for the UI work next spring.

spec-kit for Phased Modernization

Stop ad-hoc prompting. Use spec-kit to break complex migrations into structured, reviewable phases — specifications that become executable with AI assistance.

Why spec-kit for migrations? A .NET 6 → .NET 10 upgrade touches every project file, dozens of NuGet packages, Docker images, infrastructure templates, and CI/CD pipelines. spec-kit breaks this into structured phases with clear acceptance criteria — no work gets lost between sessions.

Copilot Agent Skills — Ensuring Best Practices

Alongside spec-kit, we use Copilot agent skills to ensure the migration follows .NET best practices, uses official Microsoft documentation, and applies proven upgrade patterns.

🔄 .NET Upgrade Skill

Purpose-built for framework upgrades. Handles target framework changes, NuGet compatibility, breaking change detection, and validation gates for each upgrade step.

awesome-copilot/dotnet-upgrade

How skills work with spec-kit: When Copilot agent mode executes a task from the spec, it automatically invokes these skills to look up documentation, validate patterns, and apply upgrade-specific logic. The result: code that follows official guidance without manual research.

GitHub Copilot Modernize Extension

(Colleague's Demo) — The @modernize-dotnet agent is purpose-built for .NET upgrades with 30+ specialized skills, automated assessment, and a learning agent that improves as you use it.

Three-Stage Workflow

🔍 Assessment

Examines project structure, dependencies, and code patterns. Identifies upgrade scope, breaking changes, and risk areas. Outputs assessment.md.

📋 Planning

Converts assessment into a detailed upgrade plan. Documents strategies, dependency paths, and risk mitigations. Outputs plan.md.

⚙️ Execution

Breaks plan into sequential tasks with validation. Each task is a single change with a success criterion. Creates Git commits for rollback.
